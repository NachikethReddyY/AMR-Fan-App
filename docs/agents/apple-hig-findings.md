# Apple HIG notes for the AMR fan app

Checked 25 September 2026 against Apple's [Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines). Apply these checks when designing or reviewing the Expo iOS route comparison and journey screens. Apple's guidance can change; consult the linked page again before implementation. These notes translate Apple's guidance for this project. They do not replace the product specification or set Aston Martin brand rules.

## Principles that also help on other platforms

- **Put the decision first.** A route row should make mode, time, estimated CO₂e, and provisional points easy to compare. Align like data and keep the most important content early in reading order. Make selected and unavailable routes distinguishable with text or symbols as well as color. [Layout](https://developer.apple.com/design/human-interface-guidelines/layout), [Color](https://developer.apple.com/design/human-interface-guidelines/color), [Lists and tables](https://developer.apple.com/design/human-interface-guidelines/lists-and-tables)
- **Let content resize.** The route list, headings, and bottom action must remain usable when text grows, labels wrap, or the language changes. Apple's typography guidance calls for minimal truncation at larger accessibility text sizes, including with custom fonts. [Typography](https://developer.apple.com/design/human-interface-guidelines/typography), [Layout](https://developer.apple.com/design/human-interface-guidelines/layout)
- **Give each control a clear job.** An action such as Start journey needs a button with a specific label. Route selection needs an explicit selected state. Navigation controls should move between places, not start a journey. [Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons), [Lists and tables](https://developer.apple.com/design/human-interface-guidelines/lists-and-tables), [Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars)
- **Ask for location when it becomes useful.** Request access when the person asks for a feature that needs it, explain the purpose in plain words, and provide a usable route-planning path if they deny access where one is feasible. [Privacy](https://developer.apple.com/design/human-interface-guidelines/privacy), [Core Location authorization](https://developer.apple.com/documentation/corelocation/requesting-authorization-to-use-location-services), [UIKit privacy guidance](https://developer.apple.com/documentation/uikit/protecting-the-user-s-privacy)
- **Keep status honest.** Show that routes are loading if they take time. Use measured progress only when progress is actually known. If a request stalls, explain the problem and a next step. Show errors near the affected route or task; reserve interruptive alerts for information that needs immediate action. [Loading](https://developer.apple.com/design/human-interface-guidelines/loading), [Progress indicators](https://developer.apple.com/design/human-interface-guidelines/progress-indicators), [Writing](https://developer.apple.com/design/human-interface-guidelines/writing), [Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts)

## iOS checks and values

- **Safe areas and orientation.** Keep the status bar, Dynamic Island, and home indicator clear. Anchor any persistent Start journey control to the safe area and keep scroll content reachable above it. Check portrait, landscape, Display Zoom, and smaller devices. Apple advises inset buttons instead of edge-to-edge buttons in most iOS layouts. [Layout](https://developer.apple.com/design/human-interface-guidelines/layout)
- **Touch targets.** Apple's accessibility table lists 44 × 44 pt as the recommended iOS control target and 28 × 28 pt as the minimum. Leave space between adjacent controls. Check the actual tappable route row, not just its visible text or icon. [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)
- **Geist and Dynamic Type.** Geist is a project choice, not an Apple system font. Implement scaling, Bold Text support, and wrapping for it, then inspect the largest accessibility text sizes. The fixed pixel sizes in `DESIGN.md` are starting styles, not fixed output sizes. [Typography](https://developer.apple.com/design/human-interface-guidelines/typography)
- **Appearance and contrast.** Apple expects apps to respond to the system's light and dark appearance except for uncommon justified cases. If this app remains dark-only, record that product choice. Test custom colors with Increase Contrast and in bright outdoor light. Apple's Dark Mode guidance gives 4.5:1 as a minimum foreground/background contrast ratio and recommends aiming for 7:1 for custom colors, especially small text. Apple's accessibility page gives size-specific minimums. [Dark Mode](https://developer.apple.com/design/human-interface-guidelines/dark-mode), [Color](https://developer.apple.com/design/human-interface-guidelines/color), [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)
- **Navigation and system controls.** Use top-level tabs only for top-level destinations. Keep them available as people navigate, and use the standard Back and Close behavior for deeper screens and sheets. A distinctive Aston Martin content area can coexist with familiar iOS navigation. [Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars), [Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars), [Modality](https://developer.apple.com/design/human-interface-guidelines/modality)
- **VoiceOver.** Make route choices and Start journey real accessible controls. Expose route mode, duration, emissions, provisional points, and selected or unavailable state in a useful spoken order. Ignore the decorative circuit drawing. [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility), [VoiceOver evaluation criteria](https://developer.apple.com/help/app-store-connect/manage-app-accessibility/voiceover-evaluation-criteria)

## Existing mockup choices to recheck

These are review findings from `DESIGN.md` and `prototypes/brand-directions.html`, not claims that the Expo app has the same defects.

1. `ink-muted-soft` (`#767671`) on `canvas` (`#121212`) calculates to about **4.1:1**, below the HIG's 4.5:1 minimum for small text. Recheck every text/background pairing, including text over the green circuit header and the light selected-route inset. [Dark Mode](https://developer.apple.com/design/human-interface-guidelines/dark-mode), [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)
2. The phone specimens use a fixed 790 px frame, 11–13 px metadata, and compact two-column route data. Check a native device with the largest accessibility text, long translations, and landscape before treating those measurements as app rules. The mockup's fixed frame is a presentation device. [Typography](https://developer.apple.com/design/human-interface-guidelines/typography), [Layout](https://developer.apple.com/design/human-interface-guidelines/layout)
3. The static route rows and Start journey controls are `<div>` elements. The real Expo screen needs accessible press targets, selected and disabled semantics, a visible press response, and a spoken reason when an action cannot proceed. A static HTML screenshot cannot verify those interactions. [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility), [Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons), [Lists and tables](https://developer.apple.com/design/human-interface-guidelines/lists-and-tables)
4. The mockup footer says location permission is required after Start journey. Decide when route planning truly needs device location, present the request at that moment, and show an origin-entry or other recovery path when permission is denied. [Privacy](https://developer.apple.com/design/human-interface-guidelines/privacy), [Core Location authorization](https://developer.apple.com/documentation/corelocation/requesting-authorization-to-use-location-services)
5. The mockups show planning, tracking, evidence gap, and credited copy, but no route-loading, permission-denied, network-error, or tracking-recovery interaction. Add those states before selecting a final screen layout. Keep the [product's provisional-versus-earned distinction](../../DESIGN.md) in each state. [Loading](https://developer.apple.com/design/human-interface-guidelines/loading), [Writing](https://developer.apple.com/design/human-interface-guidelines/writing), [Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts)

## Acceptance check for a working iOS screen

- On a small iPhone and in landscape, the bottom action and every route stay reachable within safe areas; no route data scrolls horizontally. [Layout](https://developer.apple.com/design/human-interface-guidelines/layout)
- At the largest accessibility text sizes, route meaning and actions remain available without clipped labels; VoiceOver announces each route's value and state. [Typography](https://developer.apple.com/design/human-interface-guidelines/typography), [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)
- Route rows and buttons have usable touch targets; selection, disabled, loading, and error states remain clear without relying only on color. [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility), [Color](https://developer.apple.com/design/human-interface-guidelines/color)
- Location permission appears at the needed step, with a specific purpose statement and a tested denial path. Route loading and tracking failures give a concrete next action. [Privacy](https://developer.apple.com/design/human-interface-guidelines/privacy), [Writing](https://developer.apple.com/design/human-interface-guidelines/writing)
- Custom colors pass a measured contrast check in each supported appearance and Increase Contrast setting. [Dark Mode](https://developer.apple.com/design/human-interface-guidelines/dark-mode), [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)

The static prototypes cannot prove safe-area behavior, touch targets, Dynamic Type, VoiceOver, permissions, or recovery. Verify these on the Expo build and an iOS device or simulator.
